# 하네스 크루: 사람 개입을 줄이는 하네스 엔지니어링 기반 개발 에이전트

> 잇츠 스터디 5기 **[엔지니어링/AI에이전트] 문제에서 에이전트까지: 하네스 엔지니어링 기반 개발 에이전트 구축** 팀의 프로젝트 저장소입니다.
> 크루원 각자가 만든 에이전트의 문서와 수행 내역을 이 저장소에 모읍니다.

Codex 기반 개발 에이전트 5종에 가드·다중 검증·피드백 루프·평가 하네스를 적용해, 사람 개입을 줄이면서도 신뢰할 수 있는 개발 자동화를 구현한 프로젝트입니다.

## 왜 이 프로젝트인가

Codex, Claude Code 같은 코딩 에이전트가 실제 코드를 만들어내지만, 실무에서 그대로 맡기기는 어렵습니다. 사람이 옆에서 계속 확인하고, 멈추고, 다시 지시해야 합니다.

우리 팀은 이 문제를 **하네스 엔지니어링**으로 풀었습니다. 에이전트가 신뢰할 수 있게 일하도록 환경·규칙·검증·피드백 루프를 설계하는 일입니다. 각자 실무나 사이드 프로젝트에서 반복되는 문제를 하나씩 골랐고, 모두 같은 방법론을 적용했습니다.

```
문제 정의 → 입출력 설계 → 실행 흐름 → 평가 기준 → 테스트 하네스 → 개선
```

## 공통 하네스 패턴

다섯 에이전트는 문제는 다르지만, 같은 질문에 각자 답을 냈습니다. **에이전트를 언제 멈추고, 무엇으로 검증하고, 실패를 어떻게 다음 실행에 반영하는가.**

| 패턴 | 적용한 에이전트 |
| --- | --- |
| 실행 가드 (승인 없는 작업 차단, 검증 근거 없는 완료 보고 차단) | 우유진 |
| 다중 검증 (여러 검증자의 합의로 통과 판정) | 조효주 |
| 근거 검증 (원문·현재 코드에 없는 판단은 거부) | 노유나, 조효주 |
| 구현 계약 (디자인·요구사항을 구현·검증 항목에 연결) | 전지원, 우유진 |
| 피드백 루프 (지적 사항을 지침·스킬·다음 작업에 반영) | 전지원, 우유진 |
| 평가 하네스 (개입 횟수·토큰·비용·대응 시간 등 지표 수집) | 우유진, 노유나, 남혜민 |
| 사람 승인 단계 설계 (언제 사람이 개입해야 하는가) | 남혜민, 우유진, 노유나 |

## 저장소 구조

```
.
├── README.md                     # 팀 프로젝트 개요 (이 문서)
├── CONTRIBUTING.md               # 팀원 갱신 방법
└── members/
    ├── _template/                # 개인 문서 템플릿
    ├── nam-hyemin/
    ├── woo-yujin/
    ├── jo-hyoju/
    ├── jeon-jiwon/
    └── noh-yuna/
```

각 크루원 폴더의 `README.md`가 그 사람 에이전트의 대표 문서입니다. 주차별 수행 내역이나 Notion에서 내보낸 문서는 같은 폴더의 `logs/`, 이미지는 `assets/`에 둡니다.
