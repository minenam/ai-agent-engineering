## 한 줄 소개

Figma와 API 명세를 받아 KMP(Android·iOS·웹) 기능을 구현하고, 필요한 검증 결과가 빠져 있으면 완료 처리를 막는 개발 에이전트입니다.

## 문제 정의

**AI에 화면 구현을 맡겨도 빠진 디자인 요소나 요구사항을 찾아 다시 지시하고, 수정한 결과도 직접 확인해야 합니다.**

- 해결할 문제: 구현을 맡긴 뒤에도 사람의 지시·검증 부담이 많이 남는다.
- 목표: 사람의 보완 지시를 줄이고, 검증 근거 없이 완료로 보고하는 일을 줄인다.
- 가설: 요구사항과 디자인 섹션을 구현 작업·검증 항목에 연결하고, 검증 근거를 완료 조건으로 요구하면 사람의 보완 지시와 검증 누락이 줄어든다.

### 해결 여부 확인 방법

| 지표 | 의미 |
| --- | --- |
| 사람 개입 횟수 | 보완 지시가 얼마나 줄었는가 |
| 자동 검증 통과율 | 구현 결과가 검증을 통과하는가 |
| 검증되지 않은 완료 보고 건수 | 근거 없이 완료라고 보고한 횟수 |
| 토큰 사용량 | 비용 |
| 요구사항 누락 수, 검토·수정 시간, 같은 문제의 재발 여부 | 1주차에 함께 제안한 지표 |

## 해결 방식

- 범위: Kotlin Multiplatform, data·domain·ui 계층, 목록·상세 기능의 구현·검증·피드백 반영
- 실행 흐름: 요구사항 → 설계 → 구현 → 검증을 연결하고, 개발자 피드백을 다음 작업에 반영
- 승인된 작업·단계·기술 계약 밖의 실행(코드 수정, 명령 실행, 작업 종료)을 막는 **실행 가드**. 운영하며 겪은 문제는 아래 "막힌 점과 배운 점" 참고

## OpenAI 기술 활용

- Codex: 코드 수정과 명령 실행 전에는 `PreToolUse`, 세션 종료 시에는 `Stop` 훅으로 승인 범위와 검증 기록을 확인합니다. [훅 설정](https://github.com/wooyj-1217/kmp_agent/blob/v0.4.14/docs/installation.md)
- OpenAI API: 직접 연동 여부는 확인이 필요합니다.

## 막힌 점과 배운 점 (6주차)

### 실행 가드가 정상 작업까지 막은 문제 (~v0.4.12)

| 단계 | 내용 |
| --- | --- |
| 문제 | 승인된 작업·단계·기술 계약 없이 코드 수정·명령 실행·종료하는 경로를 막으려고 가드를 만들었는데, 너무 세게 동작했다. v0.4.6까지 작업 중 push, 에이전트 버전 업, 작업 중간 진행이 블록됐다 |
| 원인 | 차단 여부를 판단하는 데 필요한 상태는 많았지만, 정상 작업을 이어가는 데 필요한 상태 전환과 복구 경로가 그만큼 갖춰지지 않았다 |
| 대응 | v0.4.12로 업데이트하며 기존 T2 승인을 연결해 작업 재개에 성공했다. 앱 코드 구현까지 진행했다 |
| 남은 문제 | 웹 수정 후 빌드·브라우저 검증 명령을 실행하면, 하네스가 시작 로그만 남기고 실제 테스트 프로세스를 띄우지 못한다 |

v0.4.13과 v0.4.14에서 사전 검사 지연과 잠금 대기 로그를 추가했습니다. 데모 앱의 웹 빌드와 브라우저 검증은 다시 실행해야 합니다.

막는 규칙을 늘릴 때는 막힌 뒤 정상 흐름으로 돌아가는 경로(상태 전환, 승인 연결, 복구)도 같은 수준으로 설계해야 한다.

### 지표 수집의 한계

- 사람 개입 횟수로 모은 사용자 역할 메시지 88건에 환경 지시·QA 프롬프트가 섞여 있어, 실제 개입 횟수와 분리해 유형별로 집계해야 한다.
- 토큰 사용량은 독립 QA 세션만 잡혀 있어 메인 구현 세션까지 합쳐야 전체 비용이 나온다.

## 차별점과 확장 계획

요구사항과 인수 조건을 작업별 검증 기록에 연결하고, 중단 후에도 기존 승인과 작업 시도를 이어 쓸 수 있습니다. 다음에는 수정과 재검증 기록을 같은 이슈에 묶어 피드백 재발 여부를 확인할 계획입니다.
